# Paper and defense deck

Two deliverables, both generated by script from the same source of truth (`docs/results-*.md`, `docs/perf/`,
`docs/drift/`, `docs/ablations/`, `docs/citations.md`), not hand-edited — no illustrative or placeholder
figures anywhere; every table, chart, and number is a real, executed experiment result.

- **`LogSentinel_Research_Paper.docx`** — full paper draft, Abstract through References (24 pages: Introduction,
  Related Work with corrected citations, System Design, Experimental Setup, Results E1–E8 plus ablations,
  Discussion, Threats to Validity, Conclusion). Built by `build_paper.js` (docx-js).
- **`LogSentinel_Defense.pptx`** — 12-slide defense deck with native charts and embedded result figures, built
  by `build_deck.js` (pptxgenjs). Passed schema validation and a full visual QA pass (all 12 slides rendered
  and inspected).

Placeholders that remain, by design, are the candidate's own identifying details (name, advisor, institution,
defense date) on each document's title slide/page — fill these in before submission or defense.

## Rebuilding

Re-running these after a results update reproduces a consistent document/deck instead of drifting out of sync
with the repo's data.

```bash
cd paper
npm install docx pptxgenjs      # once; not committed (node_modules is gitignored)
node build_paper.js LogSentinel_Research_Paper.docx
node build_deck.js LogSentinel_Defense.pptx
```

Figures/images are read directly from `docs/perf/*.png`, `docs/perf/e6/*.png`, and `docs/drift/*.png` at build
time (paths relative to the repo root are hard-coded near the top of each script as `FIGDIR`).

## Before submission / defense

1. Fill in the `[...]` placeholders on the paper's title page and the deck's title slide.
2. Do the manual DBLP check flagged in the paper's References section closing note (entries [1], [5], [6], [7], [8]).
3. Re-run both build scripts if any `docs/results-*.md` numbers change after this was written.
4. Rehearse the live demo using `../docs/demo-script.md` before the defense.
